Práctica para estudiantes 2

1 Propósito

En esta práctica trabajarás de manera autónoma con un registro de condiciones de cultivo de lechuga. Vas a organizar un proyecto en RStudio, importar una base de Excel, reconocer su estructura, limpiar los nombres de las variables, revisar las fechas, completar un dato faltante y guardar dos bases para análisis posteriores.

Utilizá como apoyo las teorías y prácticas guiadas anteriores. Los bloques de código se incluyen para que puedas copiarlos a tu documento Quarto, ejecutarlos, observar los resultados y responder las consignas. En algunas actividades tendrás que completar o adaptar el código.

2 Crear el proyecto lechuga

  1. Creá una carpeta llamada lechuga en una ubicación fácil de encontrar.
  2. Abrí RStudio y seleccioná File → New Project → Existing Directory para crear el proyecto dentro de esa carpeta.
  3. En el panel Files, creá las siguientes subcarpetas dentro del proyecto:
    • datos_originales: base recibida, sin modificar.
    • datos_transformados: bases nuevas o corregidas.
    • scripts: archivos .qmd y .R.
    • resultados: informes y tablas.
    • figuras: gráficos que generes más adelante.

La estructura inicial debe quedar así:

lechuga/
├── lechuga.Rproj
├── datos_originales/
├── datos_transformados/
├── scripts/
├── resultados/
└── figuras/
Recordá

Los nombres de las carpetas se escriben sin espacios, usando guiones bajos (_). Conservá intacta la base original.

3 Descargar y reconocer la base

Descargá 📥 Descargar base de datos lechuga.xlsx y guardá el archivo, con ese mismo nombre, en datos_originales.

Abrí el archivo Excel y observá la información. Antes de trabajar en R, respondé:

  1. ¿Qué tipo de archivo es lechuga.xlsx?
  2. ¿En qué hoja se encuentran los datos?
  3. ¿Cada fila corresponde a una planta o a una medición de una planta en una fecha determinada?
  4. ¿Por qué esta base puede considerarse longitudinal o de medidas repetidas?

4 Crear el documento Quarto y cargar paquetes

En RStudio, creá un documento mediante File → New File → Quarto Document y guardalo en la carpeta scripts como practica_estudiantes_2.qmd.

Si aún no instalaste los paquetes, ejecutá una sola vez en la consola:

install.packages("tidyverse")
install.packages("readxl")
install.packages("janitor")

En tu documento Quarto, copiá este bloque para cargar los paquetes:

library(tidyverse)
library(readxl)
library(janitor)

Limpiá el entorno de trabajo:

rm(list = ls())

Pregunta: ¿Cuál es la diferencia entre instalar un paquete y cargarlo con library()?

5 Importar e inspeccionar los datos

Importá la hoja lechuga del archivo Excel. Como el documento está guardado en scripts, la ruta comienza con ../, que indica subir un nivel dentro del proyecto.

lechuga <- read_excel(
  "../datos_originales/lechuga.xlsx",
  sheet = "lechuga"
)

Realizá una primera inspección:

dim(lechuga)
names(lechuga)
glimpse(lechuga)

Respondé: ¿Cuántas filas y columnas tiene la base? ¿Qué variables son numéricas? ¿Cuál identifica a cada planta?

¿Cuántas plantas distintas se registraron?

lechuga |>
  summarise(plantas_distintas = n_distinct(Plant_ID))

¿Cuántos registros tiene cada planta? ¿Todas tienen la misma cantidad?

lechuga |>
  count(Plant_ID)

Observá la variable Date en el Excel y después de importarla. ¿Las fechas aparecen escritas de la misma manera? ¿Cómo las interpreta R?

6 Limpiar los nombres de las variables

Los nombres originales pueden contener mayúsculas, espacios, paréntesis y símbolos. Normalizalos utilizando janitor::clean_names():

lechuga <- lechuga |>
  clean_names()

names(lechuga)

Respondé: ¿Qué ventajas tiene trabajar con nombres estandarizados? Revisá especialmente cómo quedaron los nombres de las variables de pH y humedad: en las actividades siguientes deberás utilizar exactamente los nombres que muestre names(lechuga).

7 Crear una fecha con formato uniforme

Creá una nueva variable fecha de clase Date. El siguiente bloque contempla cadenas con los formatos año-mes-día y mes/día/año.

lechuga <- lechuga |>
  mutate(
    fecha = coalesce(
      as.Date(as.character(date), format = "%Y-%m-%d"),
      as.Date(as.character(date), format = "%m/%d/%Y")
    )
  )

class(lechuga$fecha)
head(lechuga$fecha)
sum(is.na(lechuga$fecha))
Antes de borrar la fecha original

Verificá que la conversión sea correcta y que no haya generado fechas faltantes. Si date se importó como número de Excel o ya como fecha, habrá que adaptar la conversión antes de continuar.

Cuando hayas comprobado la conversión, eliminá la variable original:

lechuga <- lechuga |>
  select(-date)

Pregunta: ¿Qué operación realiza select(-date)? ¿Por qué conviene comprobar la conversión antes de eliminar la variable original?

8 Explorar la estructura y detectar datos faltantes

Obtené un resumen general:

summary(lechuga)

¿Cuántos valores faltantes hay en la base?

sum(is.na(lechuga))

Identificá el registro con humedad faltante:

lechuga |>
  filter(is.na(humidity_porc))

El dato faltante en la humedad de la planta 1, correspondiente al 25 de agosto de 2023, tiene como valor correcto 52. Reemplazá únicamente ese valor:

lechuga <- lechuga |>
  mutate(
    humidity_porc = case_when(
      plant_id == 1 &
        fecha == as.Date("2023-08-25") &
        is.na(humidity_porc) ~ 52,
      TRUE ~ humidity_porc
    )
  )

Comprobá que se haya realizado correctamente:

lechuga |>
  filter(plant_id == 1, fecha == as.Date("2023-08-25"))

sum(is.na(lechuga))

Respondé: ¿Por qué se agrega is.na(humidity_porc) en la condición?

humedad_3

b. ¿Cuáles fueron la temperatura, el pH y los sólidos disueltos totales de esa misma planta y fecha?

c. ¿Cuál es la primera fecha registrada cronológicamente?

lechuga_primera_fecha <- lechuga |>

nrow(lechuga_primera_fecha)

Verificá que el proyecto contenga datos_originales/lechuga.xlsx, scripts/practica_estudiantes_2.qmd, datos_transformados/lechuga_limpia.csv y datos_transformados/lechuga_primera_fecha.csv.

Renderizá tu documento Quarto, revisá el informe y guardá una copia en resultados. Antes de entregar, asegurate de que aparezcan el código, los resultados y las respuestas escritas a cada consigna.

14 ¿Qué aprendimos en esta práctica?

En esta práctica organizaste un proyecto de RStudio y desarrollaste un flujo de preparación reproducible: importaste datos desde Excel, revisaste su estructura, estandarizaste los nombres de variables, trabajaste con fechas y valores faltantes, consultaste registros y guardaste nuevas bases. El documento Quarto permite reunir el procedimiento, los resultados y las interpretaciones para revisarlos o repetirlos posteriormente.
