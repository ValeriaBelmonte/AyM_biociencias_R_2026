1 Análisis exploratorio de datos

El Análisis Exploratorio de Datos —o EDA, por sus siglas en inglés Exploratory Data Analysis— es la primera aproximación sistemática a una base de datos.

Su propósito no es obtener conclusiones definitivas, sino conocer los datos, detectar posibles problemas y formular preguntas que orienten el análisis posterior.

Antes de realizar cálculos, gráficos o modelos, necesitamos preguntarnos:

  • ¿Qué representa cada fila de la base?
  • ¿Qué información contiene cada columna?
  • ¿Qué tipos de variables tenemos?
  • ¿Hay datos faltantes, errores o valores inusuales?
  • ¿Qué patrones o relaciones comienzan a aparecer?

1.1 Objetivos principales del EDA

  1. Entender la estructura de la base

    Permite identificar la cantidad de observaciones y variables, conocer qué representa cada una y reconocer su tipo: numérica, categórica, fecha, texto, entre otros.

  2. Detectar anomalías o problemas de calidad

    Permite reconocer datos faltantes, valores atípicos, errores de carga, registros duplicados o categorías escritas de maneras diferentes.

  3. Encontrar patrones y relaciones

    A través de resúmenes y gráficos, permite observar distribuciones, diferencias entre grupos, tendencias y posibles relaciones entre variables.

  4. Formular preguntas e hipótesis iniciales

    La exploración orienta las preguntas que podremos responder con los datos y ayuda a decidir cuáles serán los siguientes pasos del análisis.

1.2 Paquetes: las herramientas que vamos a usar

R tiene muchas funciones incorporadas, pero los paquetes amplían sus posibilidades.

Podés usar la analogía de una biblioteca:

R es la biblioteca. Un paquete es una colección de libros con herramientas para una tarea. Una función es una herramienta específica dentro de ese paquete.

En este curso trabajaremos principalmente con el ecosistema tidyverse, que reúne paquetes para trabajar de manera ordenada y coherente con datos. | Paquete | ¿Para qué lo usaremos?

Paquete ¿Para qué lo usaremos?
readr Importar archivos .csv.
readxl Importar archivos de Excel.
dplyr Seleccionar, filtrar, crear y resumir variables.
tidyr Ordenar la estructura de una base.
ggplot2 Crear gráficos.
janitor Limpiar nombres de variables y tablas.
forcat para trabajar con factores

2 Importación de la base de datos

2.1 Fundamento teórico

Importar datos significa leer un archivo externo y convertirlo en un objeto que R pueda utilizar.

Para archivos CSV puede emplearse read_csv(). Esta función genera un objeto de tipo tibble, una versión moderna de un data frame.

2.2 Código en R

Suponiendo que el archivo está dentro de la carpeta datos:

Code 
datos <- read_csv("../datos originales/base_datos.csv")

Para comprobar que el objeto fue creado:

Code 
view(datos)

También puede observarse en el panel Environment de RStudio.

Para importar archivos de Excel, necesitaremos además:

Code 
install.packages("readxl") # solo la primera vez
library(readxl)            # en cada sesión

2.3 Diferencia entre objeto y archivo

El archivo original permanece almacenado en la computadora como base_datos.csv

El objeto creado dentro de R se denomina:

datos

Modificar el objeto datos no altera automáticamente el archivo CSV original.

3 Primera inspección de la base

3.0.1 Conozcamos los datos

Antes de limpiar, transformar, graficar o calcular, necesitamos responder estas preguntas:

¿Cuál es la unidad de análisis? ¿Qué representa cada fila? ¿Qué representa cada columna? ¿Cuántas observaciones y variables hay? ¿Cómo se llaman las variables? ¿Qué tipo de información contiene cada una? ¿Hay datos faltantes o valores extraños?

Funciones iniciales:

Code 
glimpse(datos)

Permite observar rápidamente:

cantidad de filas y columnas; nombres de las variables; tipo de cada variable; algunos valores de ejemplo

Code 
names(datos)

Muestra los nombres de las variables.

Code 
dim(agro)

Indica la candiad de filas y columnas

Code 
summary(datos)

Presenta un resumen general de las variables.

También pueden consultarse por separado:

número de filas y número de columnas

Code 
nrow(datos) 
ncol(datos)

4 ¿Qué significa limpiar y ordenar los datos?

Una base puede estar completa y, sin embargo, no estar lista para analizar.

La limpieza consiste en detectar y corregir problemas, por ejemplo:

nombres de variables poco claros; valores faltantes; categorías escritas de diferentes maneras; números leídos como texto; filas duplicadas; valores imposibles o inconsistentes.

Ordenar los datos significa que cada elemento tenga un lugar claro:

cada fila representa una observación; cada columna representa una variable; cada celda contiene un único valor.

Esta organización permite filtrar, resumir, graficar y analizar sin ambigüedades.

No empezamos por calcular; empezamos por comprender qué datos tenemos, cómo fueron organizados y qué calidad tienen.

EDA → importación → paquetes → conocer estructura → limpieza inicial → preguntas sobre la base.
